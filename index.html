Technical Design

The Temporal Reveal System

The Problem: Unreal’s binary level streaming broke immersion; we needed the world to organically "form" around the player. However, streaming actors individually caused severe CPU overhead.

The Solution: I decoupled the technical loading from the visual rendering to simulate a gradual load.

  • Instant Backend Load: The sub-level streams instantly with all meshes hidden.
  • The Reveal Controller: I scripted an expanding Sphere Collider that toggles mesh visibility upon overlap.
  • Visual Synchronization: This works in tandem with a timeline-driven Post-Process Mask. The mask expands perfectly alongside the collider.

Result: A smooth, narrative-compliant "world generation" effect that creates a seamless visual wave where the world appears to construct itself around the player.

Interaction Design

The Observation System

The Problem: To reduce "pixel hunting," we highlighted interactable objects. This backfired. Players began "Cursor Sweeping"; blindly scanning for outlines rather than observing the environment.

The Solution: I shifted the loop from "Finding" to "Observing" by introducing two systems:

  • The Zoom Mechanic: A dedicated optic system allowing players to scrutinize details (posters, text) from a distance.
  • Narrative Inspectables: I introduced 'Contextual Clues,' turning large set pieces into narrative discovery points that are observed in-world rather than collected

Result: This stopped players from relying on UI outlines and retrained them to visually explore the level structure for environmental clues.

Backend Engineering

Custom REST API Integration

The Challenge: The game required persistent player progression (Loadouts, Stats, Match Scores). The client needed to synchronize complex data with a custom backend without blocking the game thread.

The Solution: I engineered a C++ HTTP Subsystem to manage the full data lifecycle.

  • Async Communication: Implemented asynchronous GET/POST requests to serialize and deserialize JSON data for Player Profiles and Match History.
  • Full-Stack Implementation: I handled the entire pipeline; from parsing the raw API response to populating the Lobby, Loadout and End-of-Match UI.

Result: Achieved seamless data persistence, allowing players to customize loadouts and view real-time stats with zero UI freezing or hitching.

Systems Architecture

Data-Driven UI Framework

The Challenge: ard-coding visual properties into Blueprints meant that simple re-brands (changing themes or logos) required editing dozens of files, making iteration slow and error-prone.

The Solution: I engineered a modular architecture using C++ Base Classes and Data Assets to separate Logic from Presentation.

  • Logic in C++: Core functionality is handled in code, exposing only safe properties to the Editor.
  • Centralized Theming: Visuals are driven by a Global Data Asset. Changing a logo or color in this one asset propagates to every widget instantly.

Result: This turned a complex re-skinning task into a "one-stop process," empowering designers to update the game's look without engineering support.

Middleware Integration

Unity Audio to FMOD Integration

The Problem: The project initially relied on Unity’s native Audio system. As narrative complexity grew, this became a bottleneck. "Hard-referenced" clips meant the sound designer couldn't iterate without engineering help.

The Solution: I spearheaded the complete migration to FMOD Studio, decoupling the audio engine from gameplay logic.

  • The Abstraction Layer: I replaced direct AudioClip references with a custom Audio Manager. This bridge listens for gameplay events (e.g., PlayerDetected) and translates them into FMOD Event instances.
  • Dynamic Control: I mapped gameplay variables to FMOD Parameters. This allowed us to drive effects, like applying a Lowpass Filter during pause menu, purely through code logic.

Result: Unlocked adaptive scoring capabilities and allowed the sound team to live-mix the game without needing new builds.

Systems Design

Economy Normalization & Monetization

The Challenge: The game’s economy was unstructured with arbitrary weapon pricing, leading to erratic player progression and unclear value propositions in the store.

The Solution: I restructured the economy into a quantifiable Tiered Value System.

  • Rarity Bands: Categorized weapons into 4 distinct tiers (Normal to Gold) with strict price ranges based on power metrics (DPS/Utility).
  • Conversion Strategy: Balanced the Soft Currency economy (Weapons/Upgrades) against Hard Currency sinks (IAP Chests & Consumables) to ensure a fair "Time-to-Unlock" ratio for F2P players.
